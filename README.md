# よあコイン 経済×コレクション Discord Bot

よあコインAPI（`https://yoacoin-api.keitodaze.net/`）を使った、**「稼ぐ → 生き物を探す・手なずける → 集める」** をテーマにした Discord Bot（Python / discord.py）です。

既存カジノ（スロット等）とは別物で、ギャンブルではなく**収集・育成・やりこみ**に価値を置いています。運営主体は**一般会社**を想定し、APIは**入金検知**（と将来の**払い出し**）に使います。

## 通貨モデルと使い道

**通貨は3種類**。役割を明確に分けています。

### 🟡 よあコイン（＝グローバル通貨・全サーバー共通）
- **入手/保有**: ユーザーの実よあコイン（外部）。入金でゲームに持ち込む
- **入金**: `y!` でこの会社へ送金 → 検知して同額の**リリーコイン**を付与（`/deposit` 参照）
- **残高表示**: `/balance`。実グローバル残高の表示には新API `GET /users/{id}/balance` が必要（`BALANCE_API_ENABLED`）

### ⚜️ リリーコイン（＝ゲーム内通貨）
- **入手**: 入金（よあコイン→リリーコイン 1:1）／クエスト報酬（約8割はリリーコイン）
- **使い道**: 探索`/explore`・手なずけ・ショップ`/buy`（餌・なつき薬・ジェム）
- **換金**: `/cashout` で **よあコインに換金**（**手数料10%・数量必須**、`POST /payout`）

### 💎 ジェム（＝課金通貨・非換金）
- **入手**: リリーコインで購入（ショップの `/buy` で「ジェム」を選択。クエストでは配られない）
- **使い道**: **限定探索チケット**（`/explore premium:true`）／**金の餌**など“強い価値物”専用
- **換金**: 不可

**お金の流れ**: `よあコイン →[入金]→ リリーコイン →(遊ぶ)→[/cashout 手数料10%]→ よあコイン`。会社の利益（ハウスエッジ）は **消費されたリリーコイン**（探索/手なずけ/ショップ/ジェム）と**換金手数料**から生まれ、会社の資本（準備金）に積み上がります。

## 「会社が必ず利益」を担保する仕組み

リリーコインはよあコインの借用証（負債）なので、会社純資産 **Equity = Reserve(準備金) − Liability(発行済みリリーコイン)** で管理します。目標は **30,000 → 50,000 よあコイン**。

Equity が増える源:
- 💎 **ジェム販売**（リリーコイン→非換金ジェム。買われた分だけ純利益）※安全な主利益源
- 🎮 **ゲーム消費**（探索・手なずけ・ショップでリリーコインが消滅）
- 🧾 **換金手数料**（既定 10%）

漏れを抑えるアービトラージ対策:
- デイリーは3枠で上限固定
- 換金の最低額・クールダウン・**準備金フロアガード**（割る払い出しは拒否＝支払い保証）
- `/economy`（社長用）で準備金・負債・純資産・各利益源・「50,000までの残り」を可視化

シミュレーション（`tests/test_simulation.py`）で、実プレイ下では純資産が単調に増える（会社が黒字化する）ことを検証済みです。

## API改正提案（開発者向け）

現行APIは**よあコイン本体を払い出せません**（会社→ユーザーの送金手段が無い）。そこで開発者向けの**包括的なAPI改正提案書**を [docs/PAYOUT_API_PROPOSAL.md](docs/PAYOUT_API_PROPOSAL.md) に用意しました。

- `POST /payout` … 会社→ユーザーのよあコイン付与（換金・報酬）。冪等＋準備金フロア ※最優先
- `POST /payout/batch` … イベント/デイリーの一括付与
- `GET /payouts` … 会計突合の履歴（`/payments` と対称）
- **`GET /users/{id}/balance`** … ユーザーのグローバルよあコイン残高（`/balance` 表示用）※要望
- **`POST /charge`** … ユーザー→会社の課金（`/payout` の逆）。よあコイン→リリーコイン即時交換やジェムのよあコイン購入に必要
- 入金 Webhook … ポーリング代替（低遅延・任意）

Bot側は `payout()` / `payout_batch()` / `payouts()` / `user_balance()` / `charge()` を実装済み（フラグ制御）。採用後は対応する `*_ENABLED` を true にするだけ。

- `PAYOUT_ENABLED=true`: `/cashout` が `POST /payout` で自動払い出し（false は換金申請キュー）
- `BALANCE_API_ENABLED=true`: `/balance` に実グローバルよあコイン残高を表示
- `CHARGE_ENABLED=true`: （将来）よあコイン→リリーコイン即時交換・ジェムのよあコイン購入

## 特徴・コマンド

| コマンド | 説明 |
|----------|------|
| `/help` | すべてのコマンドの説明 |
| `/balance` | よあコイン・リリーコイン・ジェムを表示 |
| `/login` | ログインボーナス（1日1回・連続で増加・上限固定） |
| `/history` | 最近の取引履歴（購入・報酬・換金など） |
| `/quests` | デイリー(**30種テンプレから毎日3枠・日替わり**)＋通常(**50種テンプレから3枠**・進捗継続・**1日1回無料リロール**)。目標回数は難易度帯からランダム、報酬は回数に比例（約8割リリーコイン＋約2割アイテム） |
| `/deposit` | よあコイン入金の案内（→リリーコイン付与） |
| `/cashout <額>` | リリーコイン→よあコインに換金（**手数料10%・数量必須・確認あり**） |
| `/explore [エリア] [餌を使う] [限定探索]` | **エリアを選んで探索**。同エリア連続で**深度↑（レア率↑＆コスト↑）**、日替わり**天候**あり |
| `/dex` | 図鑑（通常種＋限定個体）＋**収集マイルストーン報酬** |
| `/inventory` | コレクションを開いて**生き物を選択→詳細（属性・実効ステータス・IVランク）→逃がす／合体／アイテム使用**を1画面で操作 |
| `/release <生き物>` | 生き物を**逃がして少額リリーコイン還元**（重複整理） |
| `/merge <残す> <素材>` | 同種2体を**合体**して個体値を強化（素材消費・コストあり） |
| `/badges` | 獲得したバッジ・称号を表示（未獲得は???） |
| `/ranking [分野]` | 分野別ランキング（リリー所持／図鑑／生き物数／バッジ数） |
| `/shop` `/buy <商品> [数量]` | 品揃え表示・購入（ジェムもここで購入・**確認パネルあり**） |
| `/profile [ユーザー]` | 総合プロフィール |
| `/economy` | 【社長用】経済ダッシュボード（faucet/sink内訳・**本日の純増**・自動送金状態・未処理申請） |
| `/payouts` | 【社長用】未処理の換金申請を確認・一括処理 |

生き物は**レア度＋個体値(IV)＋生息エリア**を持ち、図鑑・厳選のやりこみ要素になります。

### 探索の深化（エリア・深度・天候）
- **エリア**: 草原/森（初期解放）・水辺/雪山（図鑑進捗で解放）・洞窟/空（**エリア解放チケット**＝ジェムで解放）。エリアごとに出現種・コスト・レア分布が異なる。
- **深度**: 同じエリアを連続で探索すると深度が上がり、**レア遭遇率↑・探索コスト↑**（リスク&リワード）。別エリア/時間経過でリセット。
- **天候**: 毎日(7:00境界)替わり、特定エリアの遭遇率やレア率を確率補正。

### クエスト以外の稼ぎ / ジェムの用途
- 稼ぎ: `/login`（連続ボーナス）・`/dex` の**収集マイルストーン**・`/release`（逃がし還元）。すべて**有界＋還元<入手コスト**で会社が損しない設計。
- ジェム: 限定探索チケット・金の餌・**エリア解放チケット**・**個体値リロール薬**。

## セットアップ

1. Python 3.11+ を用意
2. 依存をインストール: `pip install -r requirements.txt`
3. 設定: `Copy-Item .env.example .env` して編集
   - `DISCORD_TOKEN` … Discord Botトークン
   - `YOACOIN_API_KEY` … `y!apikey new` で取得（`yoak_...`）
   - `COMPANY_START_RESERVE`（既定30000）, `WITHDRAW_FEE_BPS`（既定1000=10%）, `GEM_PRICE_COINS`（100）等は経済チューニング用
   - `PAYOUT_ENABLED` … 出金APIが採用されたら `true`
   - `DEV_GUILD_ID` …（任意）開発サーバーIDでスラッシュコマンド即時反映
4. Botをサーバーに招待（スコープ `bot` + `applications.commands`、権限は View Channels / Send Messages / Embed Links の最小構成でOK）

## 起動

```powershell
python bot.py
```

DB初期化 → Cogロード → スラッシュコマンド同期 → 入金ポーラ起動、が自動で走ります。

## 検証（動作確認）

```powershell
# 経済不変条件（sink>faucet・出金手数料・IV・遭遇分布・7時境界 など）
python -m tests.test_economy

# 会社純資産シミュレーション（入金→プレイ→出金で黒字化するか）
python -m tests.test_simulation

# API接続スモーク（/health・/company・/payments）
python -m api.yoacoin_client

# 入金ポーラ dry-run（カーソル進行・冪等をログ確認）
python -m api.payment_poller
```

手動フロー: `/deposit`案内 → 入金→リリーコイン付与 → `/quests`で稼ぐ → `/explore`→手なずけ → `/buy`でジェム購入→`/explore 限定探索:true` → `/cashout`(リリーコイン→よあコイン換金) → `/history`で履歴確認 → `/economy`で純資産を確認。

## 構成

```
yoacoin/
  bot.py                    # 起動・Cogロード・poller起動
  config.py                 # .env 読み込み（経済パラメータ含む）
  db.py                     # SQLite 内部台帳（準備金会計・出金・クエスト進捗）
  game.py                   # 経済定数・ロジック（純粋関数）
  quests.py                 # クエスト定義・7時境界・進捗イベント
  api/
    yoacoin_client.py       # /company /payments /payout(提案) の非同期クライアント
    payment_poller.py       # 入金ポーリング（カーソル＋冪等）→ リリーコイン付与
  cogs/
    economy.py              # /balance /help /history /quests /deposit /cashout
    collection.py           # /explore /dex /inventory + 手なずけView
    shop.py                 # /shop /buy（アイテム・ジェム購入）
    profile.py              # /profile
    admin.py                # /economy
  data/creatures.py         # 生き物カタログ（レア度・出現重み・限定個体）
  docs/PAYOUT_API_PROPOSAL.md  # 出金API提案書（開発者向け）
  tests/                    # 経済不変条件＋純資産シミュレーション
```
